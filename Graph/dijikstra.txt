1514. Path with Maximum Probability                                         A+ 
* **Problem ka Nature:** Humein source se destination tak maximum probability (product) wala path nikalna tha.
* **Dijkstra ka Idea:** Probabilities 0 se 1 ke beech hoti hain. Jab raste aage badhte hain toh multiply hokar total probability hamesha kam hoti hai. Yeh exactly "Shortest Path" jaisa behave karta hai.
* **Max-Heap (Priority Queue) ka Use:** Taki hum hamesha us node ko pehle chunein jiski probability us waqt sabse zyada ho. Isse raste baar-baar calculate nahi karne padte.
* **Step-by-Step Update:** Har node se uske neighbors ko check kiya. Agar naye raste ki probability (`curr_prob * edge_prob`) purane stored raste se zyada mili, toh usko update karke queue mein push kar diya.
* **Final Result:** Jaise hi queue khali hui (saare best paths explore ho gaye), destination node par rakhi hui probability return kar di.

1631. Path With Minimum Effort                                             A+ 
**Thought Process (Path With Minimum Effort)**

* **Main Goal:** Top-left se bottom-right jana hai aur aise raste se jana hai jisme lagatar cells ke beech ka maximum height difference kam se kam ho.
* **Dijkstra Kyun?:** Min-Heap hamesha sabse chote effort wale raste ko pehle explore karta hai, jisse faaltu lambe raste check nahi karne padte.
* **`max_abs` Array:** Yeh har cell tak pahunchne ke liye lagne wale minimum effort ko store karta hai taaki hum bar-bar kharab raste par na jayein.

**Step-by-Step Logic:**

1. **Start:** `(0,0)` ko `0` effort ke sath priority queue mein dalo.
2. **Pop:** Queue se woh cell nikalo jiska effort ab tak sabse kam hai.
3. **Explore:** Us cell ke 4 padosi (up, down, left, right) check karo.
4. **Calculate:** Naya effort nikalne ke liye dekho ki purana effort bada tha ya in dono cells ka height difference: `max(current_effort, abs(height_diff))`
5. **Update & Push:** Agar yeh naya effort padosi cell ke purane stored effort se chhota hai, toh usko update karo aur queue mein nayi value ke sath push kardo.
6. **Finish:** Jaise hi destination `(rows-1, cols-1)` queue se pop ho, wahi final answer hai.

882. Reachable Nodes In Subdivided Graph                               A      
### Thought Process

* Graph traversal ka problem hai jisme maximum allowed moves fixed hain.
* Simple BFS kaam nahi karega kyunki har edge par alag-alag intermediate nodes hain.
* **Dijkstra's Algorithm** optimal hai kyunki humein har node par **maximum remaining moves** ke sath pahuchna hai.
* Ek undirected edge par dono side se nodes cover ho sakti hain, isliye double-counting (overlap) rokna sabse zaroori hai.

---

### Algorithm Structure

* **Adjacency List:** Graph banate waqt edge weight ko `intermediate nodes + 1` set karein.
* **Priority Queue (Max-Heap):** Queue mein `{remaining_moves, current_node}` push karein taaki max moves wale raste pehle explore hon.
* **Tracking Array (`max_moves`):** Ek array banayein jo store karega ki kisi node par aate waqt max moves kitne bache the.
* **Edge Map (`used`):** Ek map use karein jo track karega ki node `u` se `v` ki taraf exactly kitni intermediate nodes cover hui.
* **Traversal Logic:** Queue se node nikal kar uske neighbors par jayen. Agar naya rasta better remaining moves de raha hai, toh array update karke queue mein push karein.
* **Final Calculation:** Total answer nikalne ke liye saari reachable original nodes ko add karein. Phir har edge ke liye overlap hata kar covered intermediate nodes add karein: `min(total_intermediate, 
used[{u,v}] + used[{v,u}])`.
